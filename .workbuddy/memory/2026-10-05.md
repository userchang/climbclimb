- **FLIP 动画**：`flip(nodes, mutate)` —— 先 `getBoundingClientRect()` 量旧中心，执行 mutate（改 hidden/appendChild），再量新中心，用 **WAAPI `n.animate()`** 从 `translate(dx,dy) base` 到 `base`。关键：`base = getComputedStyle(n).transform`，因为 `.mt .camp` 的 CSS 基础 transform 是 `translate(-50%,-50%)`（定位用），`.deck-nav .camp` 是 `none`；直接写 inline transform 会在动画结束时覆盖定位导致跳位，用 WAAPI 不动 inline style 才干净
- 进出：`peak.leaving`(opacity 0 + translateY(-16px)) / `deck.leaving` 各 .42s；panel `panel-in` .55s 上浮淡入；卡片入场兜底 140+i*90ms 手动加 `.in`（面板从 display:none 变可见时 IO 不一定触发）

### v8.1 修复：首页必须只有聚焦屏，切换不能是滚动（当前生效版）
用户反馈：点标签后"往下移动到作品栏"，不是切换。根因与修复：
- **根因**：`.peak { display: grid }` 覆盖了 UA 的 `[hidden] { display: none }`，所以 `peak.hidden = true` 不生效，deck 直接堆在首屏下面，看起来就是滚动跳转。**教训：任何显式设了 display 的容器，用 hidden 属性隐藏时都必须补一条 `.x[hidden] { display: none }`**（`.deck[hidden]` 当时写了才没出同样问题）
- **切换时序改成两段**：① 只让 `.peak-mark` + `.mt-svg` 淡出（0.3s，营地带 `.camp` 不参与淡出，因为父级 opacity 会连带子元素，必须写成后代选择器而非 `.peak.leaving` 整体）→ ② 300ms 后 `peak.hidden = true` 真正移出文档流，同时 FLIP 让营地飞到左栏（0.62s）。反过来 home() 是先 `.deck.leaving .deck-body` 淡出，再飞回
- **首页彻底单屏**：`<footer hidden>`，进层才显示；首页 = nav(64px) + peak(calc(100vh - 64px))，正好 100vh 无滚动

### v8.2 切换卡顿优化（当前生效版）
用户反馈"跳转有明显卡顿感"。四个原因 + 修法（都是通用坑，别的站也会遇到）：
1. **主因：`body { background-attachment: fixed }` + 5 层 radial-gradient**。fixed 背景每次重绘都要重算整屏渐变，切换时首屏高度骤变触发全屏重绘 → 卡。**改成 `body::before { position: fixed; inset:0; z-index:-1 }` 承载渐变**（独立合成层，视觉等价 fixed 但不再参与内容重绘），body 只留底色 `#E2EEF0`。渐变数值一字未改（锁定资产）
2. **layout thrashing**：FLIP 里 `getBoundingClientRect()` / `getComputedStyle()` / `animate()` 交替读写，每个营地强制一次同步布局 ×4。改成先批量读 first → mutate → 批量读 last 和 base → 批量写 animate
3. **响应迟滞**：FADE 300ms 后才动，像"点了没反应"。FADE 300→170，MOVE 620→480，panel-in 550→420（位移 24→14px，避免与卡片入场双重位移）
4. **回首页要等 1s 才亮完**：营地移回 `.mt` 会重播 camp-pop（延迟到 1.02s）。加 `.camp.settled`（animation:none; opacity:1），首次进层时打标记，之后不再重播
- 附带：卡片入场去掉 `rotateX(7deg)`（3D 层更贵），改 `translateY(30px) scale(.985)`；错落从 JS 一串 setTimeout 改成 CSS `nth-child` transition-delay，一次加 `.in`；`scrollTo` 显式 `behavior:'auto'` 绕开 `html{scroll-behavior:smooth}`；`.camp{will-change:transform}`

### v8.3 顿挫感根治：串行改并行交叉淡化（当前生效版）
用户反馈"还有顿挫感，过渡不够丝滑"。根因是**切换是串行的两段**，接缝处有硬切：先淡出 170ms → 然后 `peak.hidden=true` 硬切 → 才开始 FLIP。改成：
- **`.floating` 浮层技巧**：切换时给要退场的那层加 `position:absolute; top/left/right:0`，让它脱离文档流但仍在原地淡出；另一层立刻补上它的位置。两层**同时可见、交叉淡化**，中间没有任何布局突变（这是丝滑的关键，`main { position: relative }`）
- 时序全并行：t=0 同时启动 ①退场层 opacity→0(.32s) ②新层 `.deck.in .deck-body` opacity→1(.34s/延迟 .05s) ③营地 FLIP 飞 520ms；340ms 后撤掉退场层
- **只淡入 `.deck-body`**，左栏营地不参与（它们正在飞；且父级 opacity 会创建层叠上下文、连带子元素）
- 触发过渡的技巧：`display` 从 none 变可见后，先 `void el.offsetHeight` 强制落地 opacity:0，再加 `.in`；返回时同理先加 `.leaving` 再 reflow 再移除
- **去掉全部 `backdrop-filter`**（顶栏 blur 14px、窄屏标签条 blur 8px）——逐帧重算的模糊是切换掉帧大户；改用更实的半透明色（0.62→0.84）
- 缓动 `cubic-bezier(.25,1,.5,1)`（起步猛冲尾部拖沓）→ `cubic-bezier(.4,0,.2,1)`（两端都有加减速）
- 卡片入场第一张延迟 0.12s 起，与飞行错开帧预算

### v8.4 层间切换丝滑化：拆分路径 + 可打断调度（当前生效版）
用户反馈"流畅度明显提升，但连续点击不同标签不能丝滑切换"。两个根因：
1. **层→层复用了「首页→层」的整套流程**：`enter()` 里 `peak.classList.add('floating')`（peak 已 hidden，无意义）、`flip()` 计算出的 dx/dy 全是 0 却仍发起 4 个 520ms 动画、`appendChild` 到同一父节点触发 DOM 移动与重绘 —— 白白付出一整套开销
2. **互斥锁吞点击**（主因）：`if (busy || state === id) return;` + 340ms 后才解锁，连点时第二次点击被**直接丢弃**，表现为"点了没反应"

修法：
- **拆成三条路径**，由 `go(id)` 分流：`state==='home'` → `enter()`（首页→层，含 FLIP）；否则 → `swap()`（层→层：营地完全不动，只做面板交叉淡化 + 高亮 + 归顶）；`home()` 独立
- **可打断调度器** `flush()` / `settle(fn, ms)`：新切换到来时立刻执行上一次的收尾函数（必须幂等）并 `cancel()` 所有进行中的 WAAPI 动画，再以当前真实状态为起点继续。删除 `busy` 锁，只保留 `id === state` 的同层忽略
- **面板交叉淡化**：新增 `.panel.leaving { display:block; position:absolute; left/right/top:0; animation: panel-out .3s forwards }`，配合 `.deck-body { position: relative }` 做定位参照。旧面板浮起淡出、新面板同时 `panel-in`，不会把新内容顶下去
- `will-change: transform` 从 `.camp` 常驻改成只在 FLIP 那一刻设置，动画 finish/cancel 后清除（常驻会白白占用 4 个合成层）
- `prefers-reduced-motion` 段补 `.panel.leaving { animation: none }`
- 校验：CSS 括号 157/157、JS 语法通过、busy 已清除、swap/flush/settle 就位

### v8.5 修复：营地飞行动画被自己的调度器 cancel（当前生效版）
用户反馈"首页标签左移的动画没有了"。根因是 v8.4 引入的调度器自伤：
- `settle(fn, ms)` 内部第一行调了 `flush()`，而 `flip()` 刚刚把 4 个 WAAPI 动画 push 进 `running`；`enter()` 结尾再调 `settle()` → `flush()` 立刻把这 4 个动画 **cancel** 掉 → 营地不飞，直接出现在左栏
- 修法：**拆成两个函数**。`flush()` = 打断上一次（执行上一次收尾 + cancel 上一次动画），只在切换函数**开头**调用一次；`schedule(fn, ms)` = 只注册本次收尾，**绝不调 flush**。三个切换函数（enter/swap/home）均改为「开头 flush + 结尾 schedule」
- **通用教训**：做"可打断调度"时，打断动作必须严格只作用于**上一次**的资源；把"清场"和"登记"合并在一个函数里，极易误伤本轮刚创建的动画/请求。注册型函数里不要带清场副作用。

**通用教训**：连点不流畅，先查有没有"锁 + 丢事件"；有就改成"立即完成上一次收尾 + 以当前状态接续"，而不是加长/缩短锁的时长。另外切换动画要按来源分流，别让轻量路径走重量路径的代码。

### v9：作品轨道滚轮横滑 + 两侧缩小虚化（当前生效版）
用户要求：作品页加滚轮滑动（左右移动缩略图），两侧作品缩小 + 虚化。实现要点：
- **滚轮转横向**：`.rail` 上 `wheel`（`{passive:false}`），取 `|deltaX|>|deltaY| ? deltaX : deltaY`；`deltaMode` 归一化（1=行 ×16，2=页 ×100）；**滚到轨道两端就 return 不 preventDefault**，把滚动权交还页面，避免把用户困在轨道里
- **惯性引擎**：不能一次把 delta 灌进 `scrollLeft`（一跳一跳）。改成累加目标值 `glideTo`，rAF 每帧 `scrollLeft += (glideTo - scrollLeft) * 0.18`，逼近到 <0.6px 收尾。拖拽 `pointerdown` 时 `stopGlide()` 交还控制权；筛选切换、按钮翻页也统一走 `push()`
- **两侧缩小虚化**：`fx()` 按「卡片中心 vs 轨道可视中心」的距离归一化 `d = min(1, |Δ| / (railWidth*0.8))`，写 `--sc = 1 - 0.16*d` 和 inline `filter: blur(d*3.2px)`。中心卡 `filter` 置空字符串（**不能写 blur(0px)**，非 none 的 filter 会 flatten 后代的 preserve-3d，3D 倾斜层次会没）
- **缩放必须挂在 `.card-inner` 上**并合并进已有 transform：`translateY(var(--lift)) scale(var(--sc)) rotateX(var(--rx)) rotateY(var(--ry))` —— 顺序上 lift 要在 scale 前，否则抬升量被缩放
- **滚动期间必须关过渡**：`.rail.is-sliding .card-inner { transition: none }`，否则 `transform .55s` 会让缩放慢半拍；停 140ms 后移除该 class 恢复 hover 过渡
- **hover 恢复清晰**：`.rail .card:hover .card-inner { --sc: 1 !important; filter: none !important }` —— 必须 `!important`，因为这两个值都是 JS 写的 inline style
- **`scroll-snap-type` 从 mandatory 改 proximity**：mandatory 会把惯性落点强行拉回卡片起点，与自由滑动冲突
- 面板刚显形时（`light()` 的 rAF 里）要补一次 `fx()`，否则几何是上一轮的；`resize` 也要重算
- 校验：CSS 括号 159/159、JS 语法通过

### v9.1 修正：滚轮被 reduce 门控吞掉 + 虚化改「缩小变淡」（当前生效版）
用户反馈：①轨道滚不动；②不要毛玻璃 blur，要截图那种两侧缩小、变淡融入背景的效果。

- **虚化改法**：去掉 `filter: blur()`（用户嫌毛玻璃），改 `opacity = 1 - 0.58*d` + `scale = 1.04 - 0.24*d`（中心卡放大 4% 增强聚焦对比）+ `zIndex = 60 - 40*d`（中心卡盖在上层）。`.card-inner` 的 transition 加 `opacity .3s`；hover 恢复规则改成 `opacity: 1 !important`（依然是 inline style 对抗，必须 !important）

### v9.2 滚不动的真凶：scroll-snap 抵消惯性滚动（当前生效版，已实测确证）
用户反馈"滚轮只能滚一格 / 翻页按钮无效 / 没有过渡动画"。**用无头 Chrome 实测定位**（方法见下），结论：`scroll-snap-type: x proximity` 是元凶。
- 惯性滚动是**逐帧改 `scrollLeft`** 的，浏览器把每一帧都当成一次滚动操作结束，立刻吸附回最近的 snap 点 → 位移被完全抵消。对照实验数据（同环境、仅切换 snap）：
  | | 有 snap | 无 snap |
  |---|---|---|
  | 手动设 scrollLeft=200 | 被吸回 35 | =200 |
  | 滚轮一次 | 35→35 不动 | 0→328 平滑 |
  | 翻页按钮 | 35→399 一帧跳变（所以用户觉得"没有过渡动画"） | 328→1046 平滑逼近 |
- 修法：**彻底删除 `scroll-snap-type` 和 `.card { scroll-snap-align }`**。聚焦感由 JS 的缩放/淡出提供，不靠吸附。触摸 swipe 不再吸附，可接受
- 附带确认：惯性引擎逻辑本身正确（滚轮 300→收敛 330，按钮 +718 = 两张卡），`defaultPrevented=true` 说明 wheel handler 正常执行

**无头 Chrome 实测前端交互的可行配方（本机可用，值得复用）**：
- Chrome：`/c/Program Files/Google/Chrome/Application/chrome.exe`（Edge 也在）
- 命令：`chrome --headless=new --disable-gpu --no-sandbox --allow-file-access-from-files --window-size=1400,900 --virtual-time-budget=15000 --dump-dom "file:///D:/.../diag.html"`，用 grep 抓 `<pre id="out">` 的结果
- diag.html 用 iframe 载入目标页，`--allow-file-access-from-files` 才能跨域操作 file:// iframe 的 DOM
- **坑：`--headless=new` 不产生合成帧，`requestAnimationFrame` 永远不触发**（实测 `raf ran=false`）。验证 rAF 驱动的动画时，必须在 iframe 里把 `w.requestAnimationFrame` 替换成 `setTimeout(cb,16)`（同时替换 cancelAnimationFrame），虚拟时间才能推进
- 诊断要记录：`scrollWidth/clientWidth`、`matchMedia('(prefers-reduced-motion)')`、`getComputedStyle().scrollSnapType`、合成事件的 `defaultPrevented`、以及用 setTimeout 轮询出来的**数值轨迹**（比单点采样有用得多）
